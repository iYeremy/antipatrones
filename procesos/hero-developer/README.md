# Hero Developer

## Tipo

Procesos

## Descripcion

Depender de un unico desarrollador "estrella" que es el unico que entiende como funciona el sistema y que resuelve todos los problemas criticos. El exito del proyecto depende exclusivamente de que esa persona no se enferme o no renuncie.

## Como reconocerlo

* Hay una persona a la que todos le preguntan cuando algo falla.
* Nadie mas se atreve a tocar ciertas partes del codigo.
* El "heroe" suele trabajar muchas horas extras y no documenta su trabajo.

## Problemas que causa

* Crea un "Bus Factor" de 1 (si a esa persona le atropella un bus, el proyecto muere).
* El resto del equipo no aprende y se siente desmotivado.
* El heroe acaba quemado (burnout) por la presion constante.

## Mal ejemplo

Un desarrollador que escribe codigo muy complejo y "genial" pero que nadie mas puede leer, y que es el unico que puede desplegar la aplicacion.

## Buen ejemplo

Fomentar la propiedad colectiva del codigo. Todo el equipo debe entender el sistema, se hacen revisiones de codigo (Code Reviews) y la documentacion es compartida.

## Como evitarlo

* Realiza sesiones de transferencia de conocimiento periodicas.
* Obliga a que todas las partes del codigo sean tocadas por al menos dos personas diferentes.
* Valora la simplicidad del codigo sobre la "genialidad" individual.
