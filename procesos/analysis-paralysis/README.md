# Analysis Paralysis

## Tipo

Procesos

## Descripcion

Ocurre cuando se dedica demasiado tiempo a analizar y planificar un problema, hasta el punto de que el proyecto no avanza. Se busca la perfeccion antes de escribir la primera linea de codigo.

## Como reconocerlo

* Reuniones interminables sobre detalles que aun no son relevantes.
* Se crean decenas de diagramas y documentos antes de empezar a programar.
* Miedo a tomar una decision por si no es la "optima".

## Problemas que causa

* Retrasos graves en las fechas de entrega.
* Desmotivacion del equipo de desarrollo.
* Cuando por fin se empieza a programar, los requisitos pueden haber cambiado.

## Mal ejemplo

Pasar tres meses decidiendo si usar una base de datos u otra para una aplicacion que solo van a usar 10 personas.

## Buen ejemplo

Adoptar un enfoque iterativo (Agile). Tomar una decision razonable, implementarla y mejorarla segun el feedback real.

## Como evitarlo

* Define un tiempo limite para la fase de diseño.
* Acepta que ninguna decision es perfecta y que casi todo se puede cambiar luego.
* Construye un prototipo rapido (MVP) para validar ideas.
